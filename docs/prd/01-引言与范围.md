## 1.2 项目背景

院系日常管理依赖制度文件、行政材料、业务文档和内部资料。当前主要通过共享文件夹、邮件或即时通信工具管理传递，存在三类突出问题：

1. **权限边界不清**：谁能查看、下载、修改或删除某份资料，缺少统一规则与可核查的记录。
2. **审批过程不透明**：文件送到哪一步、由谁处理、是否超时，只能靠人工询问。
3. **过程记录分散**：审批意见、处理时间与经办人散落在聊天记录和邮件中，事后追查成本高。

本项目建设一套面向院系内部、部署在校园内网的轻量 OA，聚焦"资料由谁管理、哪些人可以用、文件如何审批、过程如何查询"四项基础工作，使文档管理有规则、审批流转有记录、关键操作可追溯。

## 1.3 建设目标与成功标准

### 1.3.1 目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G1 | 文档权限统一管理 | 制度文件、行政材料、业务资料分类管理，按岗位职责与资料范围设置查看、上传、下载、编辑权限 |
| G2 | 审核审批流程化 | 文件在线提交与审批，支持退回、驳回、撤回等常用处理，进度、意见与经办责任可查 |
| G3 | 分级授权与最小权限 | 按岗位与部门分配必要权限，重要权限调整留痕，减少不应查看或操作资料的情况 |
| G4 | 操作留痕与审计 | 记录登录、资料操作与审批处理，支持按人、按时间、按文档核查 |
| G5 | 统一身份认证 | 接入学校统一身份认证，沿用校内账号，不另建账号体系 |

# 2 产品定位与范围

## 2.1 产品定位

一句话定位：**面向院系内部、部署于校园内网的轻量文档权限与审批系统，把"资料权限"和"审核审批"两件事做到规则清晰、过程留痕、责任可查。**

设计原则：

1. **最小权限**：默认不可见，按岗位与资料范围逐项授权，重要权限调整走审批并留痕。
2. **流程可配置**：审批环节与审批人由管理员维护，不引入复杂流程设计器，既满足业务调整，也控制首期复杂度。
3. **全程留痕**：登录、文档操作、授权变更、审批处理均写入审计日志，日志只追加不修改。
4. **贴合现有底座**：复用 TransWeb 的运行底座（Express 会话、REST 接口配置、Vue 3 运行时组件、文件存储、部署与备份方式），OA 作为独立业务模块挂载，不改动既有 AI 能力与计费逻辑。

## 2.3 明确不做（首期边界）

以下内容本期不建设，避免范围蔓延：

1. 复杂流程设计器（拖拽节点、条件分支编排、动态表单设计器）。
2. 在线协同编辑（多人同时编辑 Word/Excel、在线批注与修订）。
3. 公文全流程（发文拟稿、签章、套红、公文交换）。
4. 会议管理、车辆管理、考勤、报销等综合办公模块。
5. 独立移动端 App（页面按响应式适配手机浏览器，不单独开发客户端）。
6. 电子签章、CA 证书签名与第三方存证（仅预留字段与接口位）。
7. 独立全文检索引擎（首期采用标题、编号、标签、摘要的数据库检索）。
8. 跨院系、跨校区的多租户运营能力（本期为单院系独立部署）。

## 2.5 技术架构基线

本项目不另起一套技术栈，而是在 TransWeb 现有运行底座上以 `oa` 业务模块的方式扩展。下表说明每一层的复用方式与改动边界，所有改动遵循"新增优先、既有逻辑最小改动、接口前缀隔离"的原则。

<!-- widths: 3.0,6.0,4.2,3.4 -->

| 层次 | 现有实现 | 本项目用法 | 改动方式 |
| --- | --- | --- | --- |
| 运行与路由 | Node.js + Express，入口 `webServer.js` | 新增 `/oa` 页面与接口守卫，复用静态服务、HTTPS、限流 | 新增中间件，不改既有路由 |
| 会话与身份 | `express-session` + `req.session.data` + `transweb-token` | 扩展部门、角色、密级、权限版本字段；接入统一认证 | 字段扩展，兼容原有判断 |
| 数据存储 | MongoDB 6.0（`MONGO_DATABASE`），MySQL/Neo4j 可选 | 新增 `oa_*` 集合，按部门与时间建索引；确需关系型时按 XML 方式扩展 | 新增集合，不影响既有集合 |
| 接口层 | `custom/RestFulConfig.js` + `interface/*.js` 自动注册 | 新增 `interface/oa.js`，按 `document/list` 分组键生成 `/oa/document/list` | 注册新 apiFile |
| 前端 | `static/` + Vue 3 运行时 SFC + Element Plus | 新增 `static/oa/` 页面与组件，复用登录条、菜单、表格组件 | 新增目录与页面 |
| 文件存储 | `multer` 上传 + `static/bucket` 桶 | 新增 OA 独立存储目录，下载走鉴权接口，不暴露静态直链 | 新增存储模块 |
| 安全能力 | 限流、CORS、CSRF 同源校验、上传类型黑名单 | 复用并收紧：OA 关闭跨站、按角色鉴权、敏感文档水印 | 配置 + 权限守卫 |
| 部署运维 | `transweb` CLI、SNI 多证书、`AdminGate` 后台闸门 | 复用部署与启停；新增每日备份、恢复演练与健康检查 | 新增运维任务 |
