## 1.2 项目背景

院系日常管理依赖制度文件、行政材料、业务文档和内部资料。当前主要通过共享文件夹、邮件或即时通信工具管理传递，存在三类突出问题：

1. **权限边界不清**：谁能查看、下载、修改或删除某份资料，缺少统一规则与可核查的记录。
2. **审批过程不透明**：文件送到哪一步、由谁处理、是否超时，只能靠人工询问。
3. **过程记录分散**：审批意见、处理时间与经办人散落在聊天记录和邮件中，事后追查成本高。

本项目建设一套面向院系内部、部署在校园内网的轻量 OA，聚焦"资料由谁管理、哪些人可以用、文件如何审批、过程如何查询"四项基础工作，使文档管理有规则、审批流转有记录、关键操作可追溯。

## 1.3 建设目标与成功标准

### 1.3.1 目标

# 2 产品定位与范围

## 2.1 产品定位

一句话定位：**面向院系内部、部署于校园内网的轻量文档权限与审批系统，把"资料权限"和"审核审批"两件事做到规则清晰、过程留痕、责任可查。**

设计原则：

1. **最小权限**：默认不可见，按岗位与资料范围逐项授权，重要权限调整走审批并留痕。
2. **流程可配置**：审批环节与审批人由管理员维护，不引入复杂流程设计器，既满足业务调整，也控制首期复杂度。
3. **全程留痕**：登录、文档操作、授权变更、审批处理均写入审计日志，日志只追加不修改。
4. **贴合现有底座**：复用 TransWeb 的运行底座（Express 会话、REST 接口配置、Vue 3 运行时组件、文件存储、部署与备份方式），OA 作为独立业务模块挂载，不改动既有 AI 能力与计费逻辑。

## 2.3 明确不做（首期边界）

以下内容本期不建设，避免范围蔓延：

1. 复杂流程设计器（拖拽节点、条件分支编排、动态表单设计器）。
2. 在线协同编辑（多人同时编辑 Word/Excel、在线批注与修订）。
3. 公文全流程（发文拟稿、签章、套红、公文交换）。
4. 会议管理、车辆管理、考勤、报销等综合办公模块。
5. 独立移动端 App（页面按响应式适配手机浏览器，不单独开发客户端）。
6. 电子签章、CA 证书签名与第三方存证（仅预留字段与接口位）。
7. 独立全文检索引擎（首期采用标题、编号、标签、摘要的数据库检索）。
8. 跨院系、跨校区的多租户运营能力（本期为单院系独立部署）。

| 层次 | 现有实现 | 本项目用法 | 改动方式 |

# 3 用户角色与权限模型

## 3.1 角色定义

系统采用"岗位角色 + 数据范围 + 文档授权"的三层模型。角色是权限的集合，数据范围限定角色能看到的数据边界，文档授权用于对个别文档做例外授予。首期设置 7 个内部角色，另将学校统一身份认证作为外部参与方纳入用例。

<!-- widths: 2.1,2.6,5.1,3.6,3.0 -->

| 编码 | 角色 | 核心职责 | 典型岗位 | 默认数据范围 |
| --- | --- | --- | --- | --- |
| LEADER | 院系领导 | 审批重要事项、查看全院文档与统计、掌握办理情况 | 院长、书记、分管副院长 | 全院（只读为主，审批按模板） |
| DOCADMIN | 文档管理员 | 维护分类目录、上传与归档、版本管理、文档库授权、回收站 | 院办资料员、档案管理员 | 全院（可管理，密级受控） |
| DEPTHEAD | 部门负责人 | 管理本部门文档、审批本部门事项、审核本部门权限申请 | 系主任、科室负责人、教研室主任 | 本部门及下级部门 |
| APPROVER | 审批人 | 处理待办、填写意见、退回或驳回、转办与催办 | 被指定的审批人员（可与其他角色叠加） | 按被分配的任务 |
| STAFF | 教职工 | 查询与下载有权限的文档、上传本人文档、发起审批、查看进度 | 全体教职工、教辅人员 | 本人 + 被授权范围 |
| SYSADMIN | 系统管理员 | 组织与用户维护、角色分配、审批模板配置、参数与备份 | 院系信息员、系统管理员 | 全院（系统配置，不默认读文档正文） |
| AUDITOR | 审计员 | 只读查询与导出审计日志、核查权限台账 | 院系纪检或指定审查人员 | 全院日志（只读） |
| IDP | 学校统一身份认证 | 提供登录认证、人员与组织信息 | 学校信息化部门 | 不进入业务数据 |

角色说明：

- 角色可叠加。例如分管副院长可同时具备 LEADER 与 APPROVER；院办资料员可同时具备 DOCADMIN 与 APPROVER。
- IDP 是外部系统角色，只参与"统一身份认证登录"与"组织人员同步"用例，不直接调用业务接口。
- 未认证访问者不属于系统角色，仅能访问登录页与说明页，不得读取任何业务数据。

## 3.2 角色组合与职责分离

### 3.2.1 组合规则

| 规则 | 说明 |
| --- | --- |
| 允许一人多角色 | 角色以集合方式授予，权限取并集，数据范围取并集 |
| 领导角色默认只读 | LEADER 默认不具备文档编辑、删除、授权能力；需要时由系统管理员显式追加 |
| 审批人按事项授权 | APPROVER 只能处理被模板或流程分配给自己的任务，不能查看无关审批 |
| 系统管理员默认不审批 | SYSADMIN 不自动获得业务审批权，避免"既当裁判又当运动员" |
| 审计员只读 | AUDITOR 对业务数据只读，对日志只读，不得导出含正文的文件 |

### 3.2.2 职责分离（不相容角色）

| 组合 | 是否允许 | 原因 |
| --- | --- | --- |
| DOCADMIN + AUDITOR | 不允许（同一人） | 文档管理员是被审计对象，审计员需保持独立 |
| SYSADMIN + AUDITOR | 不允许（同一人） | 系统管理员可改配置与权限，审计需独立 |
| SYSADMIN + APPROVER | 允许但需说明 | 小规模院系可兼任，系统需在授权时提示风险 |
| LEADER + DOCADMIN | 允许 | 分管领导可兼管资料，但敏感文档下载仍需留痕 |
| 同一人发起并审批 | 不允许 | 任何审批节点均不得由发起人本人处理 |

> 上述限制在"角色分配"页面做前端校验，并在后端接口二次校验；确需突破时由 root 账号在审计日志中留痕说明。

## 3.3 权限模型

### 3.3.1 四个层次

| 层次 | 控制对象 | 载体 | 示例 |
| --- | --- | --- | --- |
| 功能权限 | 菜单、按钮、接口 | 权限编码 permission code | doc.upload、approval.approve |
| 数据范围 | 可见的数据集合 | 角色上的 scope 字段 | 本部门及下级、本人 |
| 文档可见性 | 单份文档的可见人群 | 文档 visibility 字段 | 全院、本部门、指定角色、指定人员 |
| 文档级授权 | 例外授予或收回 | 授权记录 oa_doc_grant | 授予张三 30 天内可下载 |

### 3.3.2 判定顺序

所有文档类操作统一走以下判定，任一步失败即拒绝，不做"部分放行"：

```text
输入：用户 user、操作 action、文档 doc
1. 会话有效？           否 → 401，跳转统一认证
2. 账号状态为启用？     否 → 403，提示联系管理员
3. 功能权限包含 action？否 → 403，记录越权尝试
4. 密级是否允许？       否 → 403，提示无对应密级权限
5. 是否存在显式拒绝？   是 → 403（拒绝优先于任何授予）
6. 是否文档所有者？     是 → 按所有者权利放行（仍受密级约束）
7. 是否命中文档级授权？ 是 → 按授权范围放行（可限时、限操作）
8. 是否在角色数据范围内？是 → 放行
9. 其余情况 → 拒绝
```

### 3.3.3 关键原则

1. **默认拒绝**：新上传文档默认仅本人与文档管理员可见，需明确选择可见范围后才能提交归档。
2. **拒绝优先**：显式拒绝记录优先于角色授权与文档授权，用于处理调岗、临时限制等场景。
3. **密级优先于范围**：即使数据范围为全院，未获"敏感"密级权限的用户仍不能查看敏感文档。
4. **授权可过期**：所有文档级授权必须设置到期时间，默认 90 天，最长 365 天，到期自动失效。
5. **权限变更即时生效**：角色、授权变更后权限版本号自增，在线会话在 60 秒内刷新或被要求重新登录。
6. **超级管理员克制**：root 账号仅用于初始化与应急处置，不默认具备文档正文读取能力；如因排障需要读取，须在审计日志中记录原因。

## 3.6 组织、岗位与人员

### 3.6.1 组织模型

```text
院系（1 个）
 └── 部门 / 科室 / 教研室（N 个，支持两级）
      └── 人员（隶属一个主部门，可兼任一个兼职部门）
```

- 部门包含：部门编码、名称、上级部门、负责人、排序、状态。
- 人员包含：校内账号（学工号）、姓名、主部门、兼职部门、岗位、角色、密级权限、状态。
- 组织数据以学校统一身份认证返回为准；学校无法提供时，由系统管理员通过模板导入，并保留手工维护入口。

### 3.6.2 人员状态与生命周期

| 状态 | 含义 | 系统行为 |
| --- | --- | --- |
| 待开通 | 首次认证成功但未分配角色 | 仅可查看"等待开通"提示，不能访问业务数据 |
| 启用 | 正常使用 | 按角色与范围授权 |
| 停用 | 离职、长期休假 | 立即失效在线会话，保留历史记录与经办责任 |
| 调岗 | 部门或岗位变更 | 自动收回原部门授权，按新部门重新授权，保留审批历史 |

离职与调岗由统一认证的组织同步触发，或由系统管理员手工处理；处理动作写入审计日志，并向本人及部门负责人发送通知。

## 3.7 会话、令牌与接口授权

### 3.7.1 会话快照

沿用 TransWeb 现有会话体系（`express-session` + `req.session.data`），在原有字段基础上扩展 OA 字段，保证既有判断逻辑不受影响：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| logined | 登录成功 | 布尔值 |
| account | 统一认证账号 | 校内学工号，全局唯一 |
| folderName | 账号记录 | 个人空间标识，保持与现有平台一致 |
| name | 认证返回 | 姓名 |
| deptId / deptPath | 组织同步 | 主部门与部门路径 |
| oaRoles | 角色分配 | 如 ["STAFF","APPROVER"] |
| permissions | 角色聚合 | 权限编码数组，登录时计算 |
| clearance | 密级授权 | 如 ["public","internal"] |
| permVersion | 权限版本 | 角色或授权变更时自增 |
| sso | 认证信息 | 协议、会话标识、登录时间、最后活跃时间 |

### 3.7.2 会话策略

| 策略 | 取值 | 说明 |
| --- | --- | --- |
| 绝对有效期 | 12 小时 | 超时须重新认证 |
| 空闲超时 | 30 分钟 | 无操作自动登出，可在系统参数中调整 |
| 令牌有效期 | 24 小时 | 沿用 `transweb-token` 机制，服务端可主动失效 |
| 单点登出 | 必须 | 退出 OA 时同步调用统一认证登出接口 |
| 并发会话 | 允许 3 个 | 超出时踢出最早会话，并记录日志 |
| 权限刷新 | 60 秒 | 依据 permVersion 刷新，敏感操作前强制刷新 |

### 3.7.3 接口授权

浏览器请求使用 Cookie 会话；系统间调用使用 API Key，沿用 `custom/ApiKeyTool.js` 的 `ak_live_` 前缀、哈希存储与 Scope 机制。OA 新增以下 Scope，需同步加入 Scope 白名单：

| Scope | 允许的接口 | 说明 |
| --- | --- | --- |
| oa:doc:read | 文档查询、详情、版本列表、下载 | 下载仍需文档级权限判定 |
| oa:doc:write | 上传、编辑、归档、删除 | 需同时具备数据范围 |
| oa:approval:submit | 发起审批、撤回、催办 | 仅能操作本人发起的实例 |
| oa:approval:approve | 待办查询、同意、退回、驳回 | 仅能处理分配给自己的任务 |
| oa:audit:read | 审计日志查询与导出 | 仅授予审计类系统账号 |

约束：API Key 不得用于审批模板配置、角色分配、备份恢复等管理类接口；此类接口只允许具备对应功能权限的浏览器会话调用，且校验同源来源（沿用现有 CSRF 同源校验）。

# 5 功能需求详述

## 5.1 统一身份认证与访问控制（FR-AUTH）

模块目标：接入学校统一身份认证，沿用校内账号；在现有会话体系上补齐 OA 所需角色、部门与密级信息；提供可控的应急入口。

| 编号 | 功能 | 角色 | 优先级 | 需求描述与验收要点 |
| --- | --- | --- | --- | --- |
| FR-AUTH-001 | 统一认证登录 | 全部内部角色 | P0 | 未登录访问任意业务页面时跳转统一认证；认证成功后回跳原页面。支持 CAS、OAuth2/OIDC 两种协议适配，协议与地址由配置项决定，不写死在代码中。验收：未登录访问文档中心被拦截，登录后回到原页面；登录失败给出明确提示。 |
| FR-AUTH-002 | 首次登录自动开通 | STAFF | P0 | 首次认证成功但系统无账号时，自动创建"待开通"账号并绑定学工号、姓名、部门；页面提示"等待管理员开通"。验收：新账号首次登录不报错，管理员可在用户列表中看到待开通人员并一键开通。 |
| FR-AUTH-003 | 账号与组织映射 | 全部内部角色 | P0 | 认证返回的学工号、姓名、部门、邮箱映射到系统账号；部门不存在时挂到"未分配部门"并告警。验收：映射后可正确显示姓名与部门，部门缺失时有告警记录。 |
| FR-AUTH-004 | 单点登出与会话失效 | 全部内部角色 | P0 | 主动退出时清除本地会话并调用统一认证登出；管理员可强制某用户下线；停用账号立即失效。验收：退出后回退按钮无法再进入业务页面；强制下线在 60 秒内生效。 |
| FR-AUTH-005 | 应急本地管理员登录 | SYSADMIN | P0 | 统一认证不可用时，允许 root 管理账号通过本地入口登录，入口默认仅内网指定 IP 可访问，并强制记录审计日志。验收：断开认证服务后可用应急入口登录并完成排障；登录记录含"应急"标识。 |
| FR-AUTH-006 | 会话策略与并发控制 | 全部内部角色 | P0 | 绝对有效期 12 小时、空闲 30 分钟、单账号并发 3 个会话，超限踢出最早会话；策略可在系统参数中调整。验收：空闲超时后操作跳转登录页并给出提示；第 4 个会话登录时最早会话被踢出。 |
| FR-AUTH-007 | 账号状态联动 | SYSADMIN | P1 | 接收组织同步的离职、调岗、停用事件：停用立即失效会话并收回授权；调岗自动切换部门授权并保留历史审批。验收：模拟调岗后原部门文档不可见，新部门文档按新角色可见。 |
| FR-AUTH-008 | 登录异常告警与锁定 | SYSADMIN、AUDITOR | P1 | 同一账号连续 5 次认证失败锁定 15 分钟；异地或多 IP 频繁登录触发告警；告警在审计页面可确认。验收：连续失败触发锁定并提示剩余时间；告警列表可标记"已处理"。 |

关键规则：

- 认证协议、地址、客户端凭据全部通过环境变量与 `interface/config/common.js` 配置，代码中不出现明文密钥。
- 认证失败、锁定、强制下线、应急登录四类事件必须写审计日志，保留账号、IP、时间、结果与原因。
- 本地应急入口与统一认证入口在页面上明确区分，避免用户误用。

## 5.2 文档管理（FR-DOC）

模块目标：让资料"分类清楚、权限明确、版本可追、回收可救"。

| 编号 | 功能 | 角色 | 优先级 | 需求描述与验收要点 |
| --- | --- | --- | --- | --- |
| FR-DOC-001 | 分类目录 | DOCADMIN、SYSADMIN | P0 | 两级树形分类（如"制度文件 / 教学管理制度"），支持新增、重命名、排序、停用；停用前校验目录下无在库文档。验收：目录树正确展示，停用有在库文档的目录被拒绝并提示迁移。 |
| FR-DOC-002 | 文档上传 | DOCADMIN、DEPTHEAD、STAFF | P0 | 支持点击选择与拖拽上传；允许 PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX、TXT、MD、PNG/JPG、ZIP/RAR；单文件不超过 50 MB，单次不超过 10 个；上传时填标题、分类、标签、密级、可见范围。验收：超限文件被拒绝并提示；上传成功后出现在"我的文档"，状态为草稿。 |
| FR-DOC-003 | 批量上传 | DOCADMIN | P1 | 支持多选与文件夹上传，上传后批量设置分类与密级；单个失败不影响其他文件，生成结果清单。验收：10 个文件批量上传，失败项在清单中标红并可重试。 |
| FR-DOC-004 | 文档属性与密级 | DOCADMIN、DEPTHEAD | P0 | 维护标题、文档编号、分类、归属部门、标签、密级、可见范围、有效期、摘要；密级变更需说明理由，敏感级变更走审批。验收：属性保存后列表与详情同步更新；密级降低需审批。 |
| FR-DOC-005 | 在线预览 | 全部内部角色 | P0 | PDF、图片、文本、Markdown 直接预览；Office 文档服务端转换为 PDF 后预览并缓存；不支持格式提示下载。验收：常见格式可在浏览器内预览，转换失败有明确提示。 |
| FR-DOC-006 | 下载与水印 | 全部内部角色 | P0 | 下载走鉴权接口，不暴露静态直链；敏感文档默认添加"姓名 + 学工号 + 时间"水印；下载记录写入审计。验收：复制下载链接给无权限用户访问被拒绝；敏感文档下载件含水印。 |
| FR-DOC-007 | 文档检索 | 全部内部角色 | P0 | 按标题、文档编号、标签、上传人模糊检索，结果按相关度与时间排序，只返回有权限的文档。验收：搜索他人无权限文档不出现；分页与总数正确。 |
| FR-DOC-008 | 高级筛选 | 全部内部角色 | P1 | 按分类、部门、密级、状态、上传时间区间、文件类型组合筛选，条件可保存为常用视图。验收：组合条件结果准确，刷新后视图保留。 |
| FR-DOC-009 | 版本管理 | DOCADMIN、DEPTHEAD | P0 | 编辑或替换文件生成新版本，保留版本号、上传人、时间、变更说明；可查看、下载、回滚历史版本，回滚生成新版本。验收：同一文档存在 3 个版本，回滚后版本号递增且旧版本仍可查。 |
| FR-DOC-010 | 归档与取消归档 | DOCADMIN、DEPTHEAD | P0 | 归档后文档只读、进入正式库并可按可见范围被检索；取消归档需填写理由并留痕。验收：归档后编辑按钮不可用；取消归档后恢复可编辑。 |
| FR-DOC-011 | 回收站与恢复 | DOCADMIN、SYSADMIN | P0 | 删除进入回收站保留 30 天，支持按原路径恢复；到期自动清理；彻底删除仅系统管理员可执行。验收：删除后可恢复且版本与授权保留；30 天后自动清理。 |
| FR-DOC-012 | 删除文档 | DOCADMIN、DEPTHEAD、STAFF | P0 | 本人或管理范围内可删除，二次确认并填写原因；已归档文档需先取消归档或走删除审批（可配置）。验收：删除后列表不再显示，回收站可见；原因写入审计。 |
| FR-DOC-013 | 编辑与重命名 | DOCADMIN、DEPTHEAD、STAFF | P0 | 草稿与未归档文档可编辑元数据与文件；重命名校验同分类下标题不重复；已归档文档只读。验收：重复标题被拒绝并提示；归档后编辑入口隐藏且接口拒绝。 |
| FR-DOC-014 | 移动与复制 | DOCADMIN、DEPTHEAD | P1 | 支持移动至其他分类、复制为新文档；跨部门移动需具备目标部门管理权限；复制保留密级与标签，不复制授权。验收：移动后原位置不再显示；复制件无原授权。 |
| FR-DOC-015 | 批量操作 | DOCADMIN | P1 | 批量归档、批量移动、批量授权、批量删除；操作前展示影响条数，执行后输出成功与失败清单。验收：批量授权 20 份文档，结果清单与实际一致。 |
| FR-DOC-016 | 我的文档 | STAFF、DOCADMIN | P0 | 按草稿、审批中、已归档、被退回、回收站分组展示本人文档，支持快速提交归档与查看进度。验收：状态与审批实例一致，被退回文档显示退回原因。 |
| FR-DOC-017 | 文档详情与操作记录 | 有查看权限的角色 | P0 | 详情页展示元数据、当前版本、可见范围、授权摘要、关联审批、操作时间线；时间线含操作人、动作、时间、结果。验收：上传、编辑、授权、下载、审批均在时间线可查。 |
| FR-DOC-018 | 文档编号与命名规则 | DOCADMIN、SYSADMIN | P0 | 文档编号按"院系代码-分类代码-年份-流水号"自动生成（如 YX-ZD-2026-0001），可在参数中调整规则；文件名存储时做安全化处理，展示时保留原名。验收：编号唯一且连续；特殊字符文件名可正常上传下载。 |

关键规则：

- **文件类型安全**：沿用现有上传拦截策略，禁止 PHP、JSP、ASP、EXE、DLL、SO、SH、BAT、CMD、MSI、SCR 等可执行或脚本类型；压缩包只允许下载，不在线解压。
- **存储与访问**：文件存放于非静态目录（如 `oaStorage/files/`），仅通过下载接口流式输出并校验权限；不得放在 `static/` 下依赖静态服务直接访问。
- **版本策略**：同一文档最多保留 20 个版本，超出时归档最早版本；版本号从 V1 递增，回滚同样递增。
- **删除策略**：回收站保留 30 天，到期由定时任务清理；清理任务失败须告警。
- **水印策略**：敏感文档默认水印，包含姓名、学工号、下载时间；水印不影响正文可读性。
- **预览策略**：Office 转 PDF 使用服务端转换组件，转换结果按文档版本缓存，避免重复转换；转换失败降级为下载。

## 5.3 权限管理（FR-PERM）

模块目标：把"谁能看、谁能改、谁能授权"变成可配置、可审批、可核查的规则。

| 编号 | 功能 | 角色 | 优先级 | 需求描述与验收要点 |
| --- | --- | --- | --- | --- |
| FR-PERM-001 | 角色与成员管理 | SYSADMIN | P0 | 维护角色名称、权限编码、数据范围、状态；为人员分配或移除角色，支持批量分配与到期时间。验收：角色变更后成员菜单与接口权限同步变化（60 秒内）。 |
| FR-PERM-002 | 文档库授权 | DOCADMIN、DEPTHEAD | P0 | 对分类、部门或某批文档授予查看、下载、上传、编辑权限；可授给人员、角色或部门；必须设置用途与到期时间。验收：被授权人可见范围扩大，到期后自动失效。 |
| FR-PERM-003 | 文档级授权 | DOCADMIN、DEPTHEAD | P0 | 对单份文档临时授权，支持按人、按角色、按部门；支持"仅预览不可下载"；授权记录展示在文档详情。验收：仅预览授权下下载按钮不可用且接口拒绝。 |
| FR-PERM-004 | 权限申请 | STAFF、DEPTHEAD | P0 | 用户对某分类或某份文档申请查看、下载、编辑权限，填写用途、期限并提交审批；申请单可查看进度与结果。验收：申请提交后进入审批待办；通过后权限自动生效并记录来源。 |
| FR-PERM-005 | 权限调整审批 | DEPTHEAD、APPROVER、LEADER | P0 | 敏感权限（敏感文档、跨部门、期限超过 90 天）需经审批；审批通过后自动写入授权记录，驳回则通知申请人。验收：审批通过无需人工再授权；驳回后权限不变。 |
| FR-PERM-006 | 权限台账 | DOCADMIN、SYSADMIN、AUDITOR | P0 | 按人员、部门、文档、分类、授权来源、到期时间查询权限分布；支持导出 Excel。验收：台账与实际访问控制一致，抽样 10 条核对无差异。 |
| FR-PERM-007 | 权限到期回收 | 系统 | P0 | 授权到期前 7 天提醒被授权人与授权人；到期自动失效并记录；支持批量续期（需审批）。验收：到期后访问被拒绝，日志记录"授权到期"。 |
| FR-PERM-008 | 显式拒绝与临时限制 | SYSADMIN、DOCADMIN | P1 | 对特定人员设置临时禁止访问某分类或文档，优先级高于任何授权；解除需填写理由。验收：存在拒绝记录时，即使有授权也无法访问。 |
| FR-PERM-009 | 权限变更留痕 | 系统 | P0 | 记录授权人、被授权人、对象、权限项、有效期、审批单号、变更前后值；不可修改删除。验收：任意一次授权可在审计日志中还原完整信息。 |
| FR-PERM-010 | 权限复核 | DOCADMIN、AUDITOR | P1 | 每季度生成权限复核任务，列出长期未使用、超期、跨部门授权，逐项确认保留或收回；复核结果归档。验收：复核任务可生成、可分派、可导出结论。 |
| FR-PERM-011 | 部门负责人权限边界 | DEPTHEAD | P0 | 部门负责人只能在本部门及下级部门范围内授权；超出范围时只能提交申请，不能直接授权。验收：尝试授权其他部门文档被拒绝并提示走申请流程。 |
| FR-PERM-012 | 数据范围配置 | SYSADMIN | P0 | 角色可配置数据范围为全院、本部门及下级、本部门、本人、任务范围；范围变更需记录变更原因。验收：修改范围后列表数据量与预期一致。 |

关键规则：

- **授权三要素**：对象（人/角色/部门）、权限项（查看/下载/上传/编辑/管理）、期限，缺一不可保存。
- **授权来源**：角色授权、文档库授权、文档级授权、审批通过自动授权四类；台账需标注来源，便于回收。
- **到期提醒**：到期前 7 天、3 天、1 天各提醒一次；到期当天失效并通知。
- **禁止自我扩权**：任何人不得为自己授予超出当前角色范围的数据权限；系统管理员为他人授权时须选择审批单号或填写理由。
- **批量授权上限**：单次批量授权不超过 200 份文档，超出时分批执行。

## 5.4 审批管理（FR-APR）

模块目标：由管理员按实际业务配置审批事项，发起、流转、退回、驳回、留痕全流程可用。

| 编号 | 功能 | 角色 | 优先级 | 需求描述与验收要点 |
| --- | --- | --- | --- | --- |
| FR-APR-001 | 审批事项与模板 | SYSADMIN | P0 | 新建事项（如文档归档、敏感下载、权限申请、对外提供材料），配置适用部门、表单字段、附件要求、流程节点、时限、是否允许撤回。验收：事项启停用生效；停用后不可新发起，历史实例不受影响。 |
| FR-APR-002 | 环节与审批人配置 | SYSADMIN | P0 | 支持串行、并行会签、或签三种节点；审批人来源支持指定人员、指定角色、部门负责人、发起人上级；可设置时限与超时提醒。验收：三种节点均可跑通；审批人离职时提示需重新指定。 |
| FR-APR-003 | 表单字段配置 | SYSADMIN | P0 | 支持文本、多行文本、数字、日期、下拉、单选、多选、附件、关联文档字段；可设置必填、默认值、校验规则。验收：配置的字段在发起页正确渲染并校验。 |
| FR-APR-004 | 发起审批 | 全部内部角色 | P0 | 选择事项模板，填写表单、上传附件（可关联已有文档），提交后生成实例与首节点任务；提交前可保存草稿。验收：必填未填不能提交；提交后发起人可在"我发起的"中看到进度。 |
| FR-APR-005 | 待办列表 | 审批人 | P0 | 按紧急度、剩余时限、发起时间排序；显示事项、发起人、当前环节、剩余时间；支持批量同意（仅限简单事项且模板允许）。验收：待办数量与任务表一致；超时任务标红。 |
| FR-APR-006 | 已办列表 | 审批人 | P0 | 展示本人已处理任务及结果，可按事项、结果、时间筛选；可进入详情查看完整轨迹。验收：已办记录不可再次处理，重复提交被拒绝。 |
| FR-APR-007 | 同意 | 审批人 | P0 | 填写意见（可选或必填按模板）、可添加附件；会签节点需全部同意，或签节点任一同意即通过；通过后自动流转下一节点或办结。验收：会签 2 人仅 1 人同意时仍为处理中；全部同意后状态变为已通过。 |
| FR-APR-008 | 退回 | 审批人 | P0 | 退回至发起人或指定前序节点，必须填写退回理由；退回后实例状态为"已退回"，发起人可修改后重新提交。验收：退回后发起人收到通知，重新提交生成新轮次记录。 |
| FR-APR-009 | 驳回 | 审批人 | P0 | 终止流程，必须填写驳回理由；实例状态"已驳回"，不可继续流转，可重新发起新实例。验收：驳回后待办消失，发起人可查看理由。 |
| FR-APR-010 | 撤回 | 发起人 | P0 | 首个节点未处理时可撤回；已处理或已办结不可撤回；撤回记录留痕。验收：首节点已处理时撤回按钮不可用且接口拒绝。 |
| FR-APR-011 | 转办与加签 | 审批人 | P1 | 转办将任务转给他人并说明原因；加签在当前节点增加审批人（不超过 3 人），原审批人可选择是否继续参与。验收：转办后原处理人待办消失、新处理人收到任务；加签记录在轨迹中。 |
| FR-APR-012 | 催办与超时提醒 | 发起人、审批人 | P1 | 发起人可对停滞任务催办；系统在时限前 1 天、超时当天提醒处理人与其部门负责人；催办次数与时间记录。验收：催办后处理人收到站内信；超时任务在列表标红并计入统计。 |
| FR-APR-013 | 审批记录与轨迹 | 有查询权限的角色 | P0 | 展示实例基本信息、表单、附件、各节点处理人、意见、时间、结果、耗时；轨迹不可编辑。验收：轨迹按时间正序完整展示，含退回与重新提交轮次。 |
| FR-APR-014 | 抄送与通知 | SYSADMIN、审批人 | P0 | 支持节点抄送与办结抄送；抄送人只读；通知渠道包括站内信，邮件为可选。验收：抄送人可在"抄送我的"中查看，无法操作。 |
| FR-APR-015 | 打印与导出审批单 | 审批人、DOCADMIN | P1 | 生成含表单、意见、轨迹、二维码（实例编号）的 PDF，敏感事项加水印；导出行为记审计。验收：导出 PDF 内容完整、分页正常、二维码可识别实例编号。 |
| FR-APR-016 | 审批统计 | LEADER、SYSADMIN | P1 | 按事项、部门、时间统计发起量、办结量、退回率、驳回率、平均时长、超时率；支持导出。验收：统计口径与实例明细可核对一致。 |

关键规则：

- **模板版本**：模板修改生成新版本，已发起实例继续使用发起时的版本快照，避免"改模板影响在途流程"。
- **审批人解析**：指定人员优先于角色；角色解析到多人时按"或签"处理并全部通知，任一处理即完成；部门负责人取发起人所在部门。
- **一人多任务**：同一实例同一节点只生成一条任务；转办与加签生成子任务并保留原任务轨迹。
- **幂等与并发**：审批提交带版本号与任务状态校验，重复提交或已被他人处理时返回明确提示，不产生重复流转。
- **时限计算**：按工作日计算，节假日可在字典中维护；超时只提醒不自动通过，避免误办。
- **敏感事项**：敏感文档归档、敏感下载、跨部门授权三类事项强制走审批，不允许关闭。

- 日志保留 6 个月，重要审计日志（授权、审批、下载）保留 3 年或按学校要求。
- 审计页面不提供"删除日志"入口；数据库层禁止应用账号执行删除与更新操作（使用独立写入账号或写入前校验）。
- 备份文件加密存储，备份目录与 Web 目录分离，备份下载需二次确认并留痕。

### UC-001 统一身份认证登录

<!-- widths: 3.0,13.5 -->

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-001 |
| 参与者 | 教职工、部门负责人、审批人、领导、文档管理员、系统管理员、审计员；学校统一身份认证（IDP） |
| 优先级 | P0 |
| 关联需求 | FR-AUTH-001、FR-AUTH-003、FR-AUTH-004、FR-AUTH-006 |
| 前置条件 | 用户已在学校统一身份认证中拥有有效账号；OA 已完成认证参数配置 |
| 触发条件 | 用户访问 OA 任意业务页面或点击"统一认证登录" |

**主流程：**

1. 用户访问 OA 页面，系统检测到无有效会话，跳转统一认证登录页并携带回跳地址。
2. 用户在统一认证页完成账号密码或学校要求的认证方式。
3. 认证成功后，IDP 携带票据回跳 OA 回调地址。
4. OA 校验票据，获取学工号、姓名、部门、邮箱等属性。
5. OA 查询本地账号：存在则加载角色、部门、密级与权限版本；不存在则创建"待开通"账号（见 UC-002）。
6. OA 写入会话快照，记录登录日志，跳转回原访问页面。
7. 页面按角色渲染菜单与工作台数据。

**异常与分支：**

- 4a 票据无效或过期：提示"登录已失效，请重新登录"，重新跳转认证，不建立会话。
- 4b IDP 返回缺少学工号：记录错误日志并提示"账号信息不完整，请联系管理员"，不建立会话。
- 5a 账号状态为停用：提示"账号已停用"，记录失败原因，不建立会话。
- 5b 账号状态为待开通：进入待开通提示页，仅可查看提示与联系方式。
- 6a 并发会话超过 3 个：踢出最早会话并提示"已在其他设备登录"。

**后置条件：** 用户会话建立；登录日志写入；权限版本记录到会话。

**业务规则：** 登录失败不区分"账号不存在"与"密码错误"提示；认证过程不记录用户密码；会话 Cookie 必须为 HttpOnly 且按 HTTPS 自动安全标记。

### UC-004 上传文档并提交归档

| 项目 | 内容 |

**主流程：**

1. 用户选择文件（或拖拽），系统校验类型、大小与数量。
2. 用户填写标题、分类、标签，选择密级（公开/内部）与可见范围。
3. 系统上传文件，生成草稿文档与 V1 版本，状态为"草稿"。
4. 用户在"我的文档"中点击"提交归档"，系统展示归档确认页（分类、密级、可见范围、审批人）。

- 5b 审批被驳回：文档保持草稿状态，可修改后重新发起。

# 7 业务规则与状态机

## 7.1 文档生命周期

```text
主流程：上传 → 草稿(DRAFT) → 提交归档 → 审批中(SUBMITTED) → 全部通过 → 已归档(ACTIVE)
有效期：已归档(ACTIVE) → 有效期到 → 已过期(EXPIRED) → 续期审批 → 已归档(ACTIVE)
退回：  审批中(SUBMITTED) → 退回 → 被退回(RETURNED) → 修改后再提交 → 审批中（轮次 +1）
驳回：  审批中(SUBMITTED) → 驳回 → 草稿(DRAFT)
删除：  任意状态（审批中除外） → 删除 → 回收站(RECYCLED) → 恢复 → 原状态
清理：  回收站(RECYCLED) → 彻底删除 → 已删除(DELETED，仅保留审计快照)
```

| 当前状态 | 事件 | 目标状态 | 操作者 | 条件 | 留痕 |
| --- | --- | --- | --- | --- | --- |
| 无 | 上传成功 | 草稿 | 有上传权限者 | 类型、大小、分类合法 | 上传日志 |
| 草稿 | 提交归档 | 审批中 | 文档所有者 | 属性完整、审批模板可用 | 提交日志 + 审批实例 |
| 审批中 | 审批通过 | 已归档 | 审批人 | 全部节点通过 | 审批轨迹 |
| 审批中 | 退回 | 被退回 | 审批人 | 填写退回理由 | 审批轨迹 |
| 审批中 | 驳回 | 草稿 | 审批人 | 填写驳回理由 | 审批轨迹 |
| 被退回 | 修改后再提交 | 审批中 | 文档所有者 | 修改内容并确认 | 新轮次记录 |
| 已归档 | 取消归档 | 草稿 | 文档管理员 | 填写理由、具备权限 | 归档日志 |
| 已归档 | 有效期到 | 已过期 | 系统 | 到期任务执行 | 状态变更日志 |
| 已过期 | 续期 | 已归档 | 文档管理员 | 审批通过（可配置） | 审批 + 状态日志 |
| 任意（非审批中） | 删除 | 回收站 | 所有者/管理员 | 二次确认、填写原因 | 删除日志 |
| 回收站 | 恢复 | 删除前状态 | 文档管理员 | 未超 30 天 | 恢复日志 |
| 回收站 | 彻底删除 | 已删除 | 系统管理员 | 二次确认 | 删除日志 |

> 处于"审批中"的文档不允许编辑、移动、删除或回滚，避免在途审批与内容不一致。

## 7.2 审批状态机

### 7.2.1 实例状态

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| DRAFT | 草稿 | 编辑、提交、删除 |
| PENDING_ASSIGN | 待分配（审批人缺失） | 管理员指定审批人、终止 |
| RUNNING | 审批中 | 同意、退回、驳回、撤回、催办、转办、加签 |
| RETURNED | 已退回 | 发起人修改后重新提交、终止 |
| REJECTED | 已驳回 | 查看、重新发起（新实例） |
| WITHDRAWN | 已撤回 | 查看、重新发起 |
| APPROVED | 已通过 | 查看、打印、导出 |
| CANCELLED | 已终止 | 查看 |

### 7.2.2 任务状态

| 状态 | 含义 |
| --- | --- |
| PENDING | 待处理 |
| APPROVED | 已同意 |
| RETURNED | 已退回 |
| REJECTED | 已驳回 |
| TRANSFERRED | 已转办（原任务关闭） |
| SKIPPED | 已跳过（或签中他人已处理） |
| CANCELLED | 已取消（撤回、终止或流程结束） |

### 7.2.3 流转规则

1. **串行节点**：前一节点全部任务完成后生成下一节点任务；最后一节点通过后实例置 APPROVED。
2. **会签节点**：节点内全部任务为 APPROVED 才通过；任一任务 RETURNED 则节点退回；任一任务 REJECTED 则实例驳回。
3. **或签节点**：任一任务 APPROVED 即通过，其余任务置 SKIPPED；任一任务 REJECTED 则实例驳回。
4. **退回**：默认退回至发起人；模板允许时可退回至指定前序节点，该节点之后的任务全部置 CANCELLED，实例状态 RETURNED。
5. **重新提交**：发起人修改后提交，轮次 round 加 1，生成新的任务集合；历史轨迹保留。
6. **撤回**：仅 RUNNING 且首节点无任何处理记录时允许；撤回后所有 PENDING 任务置 CANCELLED。
7. **终止**：管理员可终止异常实例，必须填写原因并通知参与人。
8. **幂等**：处理任务时携带 `taskVersion`，服务端 `findOneAndUpdate({taskId, status:"PENDING", version:taskVersion})`，未命中即返回"任务已处理"。

### 7.2.4 时限规则

- 时限以小时配置，按工作日 9:00—18:00 折算；节假日从字典读取。
- 时限前 1 天提醒一次，超时当天提醒一次并标红；不自动通过、不自动驳回。
- 超时任务计入部门统计，连续 3 次超时的审批人由系统管理员提醒。

## 7.3 权限判定规则

### 7.3.1 判定伪代码

```text
function can(user, action, doc):
    if not user.logined: return DENY(401)
    if user.status != "active": return DENY(403, "账号不可用")
    if action not in user.permissions: return DENY(403, "无功能权限")
    if doc.classification not in user.clearance: return DENY(403, "无密级权限")
    if exists_deny(user, doc): return DENY(403, "已被限制")
    if doc.ownerAccount == user.account:
        return ALLOW(min(user.ownerRights, action, doc.status))
    grant = match_grant(user, doc, action)
    if grant and grant.valid: return ALLOW(grant.rights)
    if in_scope(user, doc) and action in scope_rights(user): return ALLOW
    return DENY(403, "无权访问")
```

## 8.4 索引与容量估算

索引原则：

- 所有列表查询必须命中索引，禁止全表扫描；常用筛选字段建组合索引，遵循"等值在前、范围在后"。
- 审计日志按月分区思路设计：保留 `ts` 索引，历史数据按年归档到独立集合或文件。
- 唯一索引用于业务编号：`docNo`、`instanceNo`、`code`、`account`。
- 软删除文档保留在 `oa_document`，通过 `status` 过滤；回收站查询使用 `status + deletedAt` 组合索引。

容量估算（500 用户、5 万文档）：

| 项目 | 估算 |
| --- | --- |
| 文档文件 | 平均 2 MB × 5 万 = 100 GB |
| 历史版本 | 平均 3 个版本，增量约 150 GB |
| 预览缓存 | 约占原文件 20%，约 50 GB |
| 数据库 | 文档元数据与日志约 20 GB |
| 备份 | 全量 + 增量保留 30 天，约需 2 倍空间 |
| 建议磁盘 | 1 TB 起步，预留 20% 余量 |

### 8.5.2 访问控制

1. 文件目录权限设为 `0700`，仅服务进程账号可读写；不放在 `static/` 下，避免被 `express.static` 直接命中。
2. 下载与预览统一走 `/oa/document/download`、`/oa/document/preview` 接口，先鉴权再流式输出。
3. 响应头设置 `Content-Disposition: attachment`（下载）与 `X-Content-Type-Options: nosniff`；预览接口按白名单 MIME 输出。
4. 支持 `Range` 请求，便于大文件断点续传与 PDF 分段加载。
5. 文件哈希（SHA-256）入库，下载时可校验完整性；同一文件重复上传按哈希去重，节省空间。
6. 临时文件沿用现有清理机制（每小时清理 30 分钟前的临时文件），并增加 OA 专用临时目录。

## 9.4 与现有框架的集成

| 集成点 | 做法 | 影响范围 |
| --- | --- | --- |
| 接口注册 | `interface/index.js` 的 `apiFiles` 增加 `oa: "oa.js"`；`interface/oa.js` 用 `document/list`、`approval/todo` 等分组键导出任务，`RestFulConfig` 生成 `/oa/document/list` 这类路径；也可拆成 `oa.js`、`oaApproval.js` 多个 apiFile 分别注册 | 新增文件，不改动既有接口 |
| 鉴权 | 新增 `custom/OaAuth.js`：`require(permission, handler)` 统一校验会话、账号状态、功能权限、密级；API Key 通过 `requiredScope` 校验 | 仅 OA 接口使用 |
| 审计 | 新增 `custom/OaAudit.js`：提供 `write(event)` 与 `wrap(action)`，业务成功后同步写入 | 仅 OA 接口使用 |
| 文件 | 新增 `custom/OaStorage.js`：保存、读取、流式输出、哈希、水印、临时清理 | 独立目录，不影响 bucket |
| 认证 | 新增 `custom/OaSso.js`：CAS 与 OIDC 适配，参数来自 `common.js` 与 `.env` | 新增入口，保留本地应急登录 |
| 页面守卫 | `webServer.js` 在 `express.static` 之前增加 `/oa/` 守卫：未登录访问业务页 302 到 `/oa/login.html`，登录页与静态资源放行 | 新增中间件，顺序与现有 `/bucket/personal/` 守卫一致 |
| 索引初始化 | 新增 `custom/OaDb.js` 的 `ensureIndexes()`，服务启动时调用一次，失败降级为告警不阻塞启动 | 启动阶段 |
| 配置 | `interface/config/common.js` 增加 `oa` 段：`session`、`upload`、`watermark`、`sso`、`approval`、`storage` | 追加配置，既有配置不变 |
| 环境变量 | `.env` 增加 `OA_SSO_PROTOCOL`、`OA_SSO_LOGIN_URL`、`OA_SSO_VALIDATE_URL`、`OA_SSO_CLIENT_ID`、`OA_SSO_CLIENT_SECRET`、`OA_SSO_REDIRECT_URI`、`OA_STORAGE_ROOT` | 新增变量，示例写入 `.env.example` |

> 所有改动遵循"新增文件优先、既有逻辑最小改动"的原则；不修改既有 `/user`、`/gpt`、`/admin` 行为，确保平台原有功能与计费不受影响。

## 10.3 前端实现约定

| 约定 | 说明 |
| --- | --- |
| 技术栈 | Vue 3 + Element Plus，沿用 `ElementVueItem` 运行时加载 SFC，不引入 Vite/Webpack |
| 页面结构 | HTML 壳负责 SEO、静态资源与挂载点；业务逻辑放在 `.vue` 组件，通过 `interface` 声明接口地址 |
| 组件复用 | 复用 `static/components/loginBar.vue`、`menu.vue`、`infoCardList.vue` 与 `static/plugins/elementVueItem/dataTable.vue` 等既有组件 |
| 样式规范 | 遵循 AGENTS.md：禁止使用 `:deep()`、`::v-deep`、`>>>`、`/deep/` 深度选择器；通过 props、class、插槽覆盖子组件样式 |
| 响应式 | 断点 1366 / 1024 / 768；小于 768 时侧边栏折叠、表格转卡片、操作收进"更多" |
| 状态处理 | 统一封装 loading、空状态、错误态；401 跳登录、403 跳无权限页、ret!=0 用消息提示 |
| 安全 | 文件名称与富文本做转义；不在 URL 中传令牌；下载走接口，不拼接静态路径 |
| 可访问性 | 表单 label 关联、键盘可操作、对比度符合 WCAG AA、图标按钮提供 title |
| 国际化 | 默认中文，文案集中在 `static/oa/i18n/zh.js`，预留英文文件 |
| 性能 | 列表虚拟滚动（超过 200 条）、图片懒加载、预览按需加载、接口并发不超过 5 个 |

## 11.2 安全与合规

按网络安全等级保护二级要求落实，重点控制项如下：

| 控制点 | 措施 |
| --- | --- |
| 身份鉴别 | 统一身份认证；密码不出现在日志；连续失败锁定；会话超时与并发控制 |
| 访问控制 | RBAC + 数据范围 + 文档授权 + 密级；默认拒绝；接口逐项鉴权；越权尝试记日志 |
| 安全审计 | 登录、文档、授权、审批、配置全留痕；日志只追加；保留不少于 6 个月；支持完整性校验 |
| 数据完整性 | 文件 SHA-256 校验；审批与授权使用乐观锁；备份校验值 |
| 数据保密性 | 传输 TLS；敏感文档水印；备份加密；密钥放 `.env` 不入库不入代码 |
| 备份恢复 | 每日备份，保留 30 天；季度恢复演练；RPO ≤ 24 小时、RTO ≤ 4 小时 |
| 剩余信息保护 | 删除文件后清理存储；临时文件定时清理；会话登出即失效 |
| 个人信息保护 | 仅采集必要信息；手机号、邮箱脱敏展示；导出需授权并留痕 |
| 上传安全 | 类型白名单 + 黑名单双重校验；大小限制；文件名安全化；不在服务端执行上传内容 |
| Web 安全 | 沿用 CSRF 同源校验、CORS 白名单、限流、XSS 转义、点击劫持防护 |
| 权限最小化 | 内置角色最小权限；系统管理员不默认读正文；临时授权到期回收 |

## 11.5 可维护性与扩展性

1. **配置化**：审批模板、字典、参数均可在界面配置，减少改代码。
2. **接口分层**：页面只依赖 `/oa` 接口；后续替换数据库或接入学校其他系统时不影响前端。
3. **数据库可替换**：数据访问封装在 `custom/OaDb.js`，如需 MySQL，可按现有 `interface/xml` 方式新增查询配置并实现同一接口。
4. **预留扩展点**：电子签章、短信通知、企业微信/钉钉、全文检索引擎均以适配器方式预留，不侵入核心流程。
5. **日志规范**：统一 `requestId` 串联前后端日志，便于排障。
6. **文档与交接**：交付接口文档、数据字典、部署手册、运维手册与操作手册，确保院系可自行维护。
