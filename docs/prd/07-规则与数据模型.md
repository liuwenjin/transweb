# 7 业务规则与状态机

## 7.1 文档生命周期

```text
主流程：上传 → 草稿(DRAFT) → 提交归档 → 审批中(SUBMITTED) → 全部通过 → 已归档(ACTIVE)
有效期：已归档(ACTIVE) → 有效期到 → 已过期(EXPIRED) → 续期审批 → 已归档(ACTIVE)
退回：  审批中(SUBMITTED) → 退回 → 被退回(RETURNED) → 修改后再提交 → 审批中（轮次 +1）
驳回：  审批中(SUBMITTED) → 驳回 → 草稿(DRAFT)
删除：  任意状态（审批中除外） → 删除 → 回收站(RECYCLED) → 恢复 → 原状态
清理：  回收站(RECYCLED) → 彻底删除 → 已删除(DELETED，仅保留审计快照)
```

| 当前状态 | 事件 | 目标状态 | 操作者 | 条件 | 留痕 |
| --- | --- | --- | --- | --- | --- |
| 无 | 上传成功 | 草稿 | 有上传权限者 | 类型、大小、分类合法 | 上传日志 |
| 草稿 | 提交归档 | 审批中 | 文档所有者 | 属性完整、审批模板可用 | 提交日志 + 审批实例 |
| 审批中 | 审批通过 | 已归档 | 审批人 | 全部节点通过 | 审批轨迹 |
| 审批中 | 退回 | 被退回 | 审批人 | 填写退回理由 | 审批轨迹 |
| 审批中 | 驳回 | 草稿 | 审批人 | 填写驳回理由 | 审批轨迹 |
| 被退回 | 修改后再提交 | 审批中 | 文档所有者 | 修改内容并确认 | 新轮次记录 |
| 已归档 | 取消归档 | 草稿 | 文档管理员 | 填写理由、具备权限 | 归档日志 |
| 已归档 | 有效期到 | 已过期 | 系统 | 到期任务执行 | 状态变更日志 |
| 已过期 | 续期 | 已归档 | 文档管理员 | 审批通过（可配置） | 审批 + 状态日志 |
| 任意（非审批中） | 删除 | 回收站 | 所有者/管理员 | 二次确认、填写原因 | 删除日志 |
| 回收站 | 恢复 | 删除前状态 | 文档管理员 | 未超 30 天 | 恢复日志 |
| 回收站 | 彻底删除 | 已删除 | 系统管理员 | 二次确认 | 删除日志 |

> 处于"审批中"的文档不允许编辑、移动、删除或回滚，避免在途审批与内容不一致。

## 7.2 审批状态机

### 7.2.1 实例状态

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| DRAFT | 草稿 | 编辑、提交、删除 |
| PENDING_ASSIGN | 待分配（审批人缺失） | 管理员指定审批人、终止 |
| RUNNING | 审批中 | 同意、退回、驳回、撤回、催办、转办、加签 |
| RETURNED | 已退回 | 发起人修改后重新提交、终止 |
| REJECTED | 已驳回 | 查看、重新发起（新实例） |
| WITHDRAWN | 已撤回 | 查看、重新发起 |
| APPROVED | 已通过 | 查看、打印、导出 |
| CANCELLED | 已终止 | 查看 |

### 7.2.2 任务状态

| 状态 | 含义 |
| --- | --- |
| PENDING | 待处理 |
| APPROVED | 已同意 |
| RETURNED | 已退回 |
| REJECTED | 已驳回 |
| TRANSFERRED | 已转办（原任务关闭） |
| SKIPPED | 已跳过（或签中他人已处理） |
| CANCELLED | 已取消（撤回、终止或流程结束） |

### 7.2.3 流转规则

1. **串行节点**：前一节点全部任务完成后生成下一节点任务；最后一节点通过后实例置 APPROVED。
2. **会签节点**：节点内全部任务为 APPROVED 才通过；任一任务 RETURNED 则节点退回；任一任务 REJECTED 则实例驳回。
3. **或签节点**：任一任务 APPROVED 即通过，其余任务置 SKIPPED；任一任务 REJECTED 则实例驳回。
4. **退回**：默认退回至发起人；模板允许时可退回至指定前序节点，该节点之后的任务全部置 CANCELLED，实例状态 RETURNED。
5. **重新提交**：发起人修改后提交，轮次 round 加 1，生成新的任务集合；历史轨迹保留。
6. **撤回**：仅 RUNNING 且首节点无任何处理记录时允许；撤回后所有 PENDING 任务置 CANCELLED。
7. **终止**：管理员可终止异常实例，必须填写原因并通知参与人。
8. **幂等**：处理任务时携带 `taskVersion`，服务端 `findOneAndUpdate({taskId, status:"PENDING", version:taskVersion})`，未命中即返回"任务已处理"。

### 7.2.4 时限规则

- 时限以小时配置，按工作日 9:00—18:00 折算；节假日从字典读取。
- 时限前 1 天提醒一次，超时当天提醒一次并标红；不自动通过、不自动驳回。
- 超时任务计入部门统计，连续 3 次超时的审批人由系统管理员提醒。

## 7.3 权限判定规则

### 7.3.1 判定伪代码

```text
function can(user, action, doc):
    if not user.logined: return DENY(401)
    if user.status != "active": return DENY(403, "账号不可用")
    if action not in user.permissions: return DENY(403, "无功能权限")
    if doc.classification not in user.clearance: return DENY(403, "无密级权限")
    if exists_deny(user, doc): return DENY(403, "已被限制")
    if doc.ownerAccount == user.account:
        return ALLOW(min(user.ownerRights, action, doc.status))
    grant = match_grant(user, doc, action)
    if grant and grant.valid: return ALLOW(grant.rights)
    if in_scope(user, doc) and action in scope_rights(user): return ALLOW
    return DENY(403, "无权访问")
```

### 7.3.2 判定示例

<!-- widths: 4.5,4.0,4.0,4.0 -->

| 场景 | 用户 | 文档 | 结果 |
| --- | --- | --- | --- |
| 本部门负责人查看本部门内部文档 | DEPTHEAD，本部门 | 内部，归属本部门 | 允许（数据范围命中） |
| 教职工查看他部门内部文档 | STAFF，A 部门 | 内部，归属 B 部门 | 拒绝（范围不命中，无授权） |
| 被授权人查看敏感文档 | STAFF，具备敏感密级 | 敏感，已授权查看 | 允许查看，不允许下载（授权仅查看） |
| 敏感文档下载 | STAFF，无敏感密级 | 敏感 | 拒绝（密级优先） |
| 显式拒绝后访问 | 已存在拒绝记录 | 任意 | 拒绝（拒绝优先） |
| 审批人查看任务关联文档 | APPROVER | 任务范围内的敏感文档 | 允许查看（任务范围例外，仅限该实例） |
| 文档所有者编辑已归档文档 | STAFF | 已归档 | 拒绝（状态限制） |

> 审批人的"任务范围例外"仅在其待办任务存续期间有效，任务办结后自动失效，且不授予下载权限。

## 7.4 编号、版本与并发规则

| 规则 | 说明 |
| --- | --- |
| 文档编号 | `院系代码-分类代码-年份-四位流水`，如 YX-ZD-2026-0001；流水按分类与年份独立自增，使用原子计数器避免重复 |
| 审批单号 | `SP-年份-四位流水`，如 SP-2026-0123 |
| 授权单号 | `SQ-年份-四位流水` |
| 版本号 | V1 起递增，回滚生成新版本，不复用旧版本号 |
| 文件命名 | 存储名 `v{版本号}_{sha256前8位}.{ext}`，展示名保留原始文件名并做安全过滤 |
| 并发控制 | 文档元数据更新使用 `updatedAt` 或 `version` 字段做乐观锁；审批任务使用 `taskVersion`；授权写入使用唯一索引去重 |
| 幂等 | 上传使用客户端生成的 `uploadId` 去重；审批提交使用 `requestId` 去重，重复请求返回首次结果 |

## 7.6 审计规则

| 规则 | 说明 |
| --- | --- |
| 必记事件 | 登录成功/失败/登出、上传、预览、下载、编辑、删除、恢复、归档、授权、收回、审批处理、配置变更、数据导入、备份恢复、导出 |

| 保留期限 | 登录与操作日志不少于 6 个月；授权、审批、下载日志不少于 3 年（可按学校要求调整） |

## 8.4 索引与容量估算

索引原则：

- 所有列表查询必须命中索引，禁止全表扫描；常用筛选字段建组合索引，遵循"等值在前、范围在后"。
- 审计日志按月分区思路设计：保留 `ts` 索引，历史数据按年归档到独立集合或文件。
- 唯一索引用于业务编号：`docNo`、`instanceNo`、`code`、`account`。
- 软删除文档保留在 `oa_document`，通过 `status` 过滤；回收站查询使用 `status + deletedAt` 组合索引。

容量估算（500 用户、5 万文档）：

| 项目 | 估算 |
| --- | --- |
| 文档文件 | 平均 2 MB × 5 万 = 100 GB |
| 历史版本 | 平均 3 个版本，增量约 150 GB |
| 预览缓存 | 约占原文件 20%，约 50 GB |
| 数据库 | 文档元数据与日志约 20 GB |
| 备份 | 全量 + 增量保留 30 天，约需 2 倍空间 |
| 建议磁盘 | 1 TB 起步，预留 20% 余量 |

## 8.5 文件存储方案

### 8.5.1 目录结构

<!-- widths: 7.0,9.6 -->

| 路径 | 说明 |
| --- | --- |
| oaStorage/files/deptCode/yyyy/MM/docId/ | 按部门、年月与文档分层存放版本文件 |
| v1_ab12cd34.pdf、v2_ef56gh78.docx | 存储名为 v{版本号}_{哈希前 8 位}.{扩展名} |
| oaStorage/preview/docId/v2.pdf | Office 转换为 PDF 的预览缓存 |
| oaStorage/tmp/ | 上传临时文件，定时清理 |
| oaStorage/backup/ | 备份清单与校验值（备份实体建议独立磁盘） |


### 8.5.2 访问控制

1. 文件目录权限设为 `0700`，仅服务进程账号可读写；不放在 `static/` 下，避免被 `express.static` 直接命中。
2. 下载与预览统一走 `/oa/document/download`、`/oa/document/preview` 接口，先鉴权再流式输出。
3. 响应头设置 `Content-Disposition: attachment`（下载）与 `X-Content-Type-Options: nosniff`；预览接口按白名单 MIME 输出。
4. 支持 `Range` 请求，便于大文件断点续传与 PDF 分段加载。
5. 文件哈希（SHA-256）入库，下载时可校验完整性；同一文件重复上传按哈希去重，节省空间。
6. 临时文件沿用现有清理机制（每小时清理 30 分钟前的临时文件），并增加 OA 专用临时目录。

### 8.5.3 与现有能力的复用

| 能力 | 复用方式 |
| --- | --- |
| 上传解析 | 复用 `multer` 与现有文件类型黑名单，增加 OA 白名单与 50 MB 限制 |
| 静态资源 | OA 页面放在 `static/oa/`，由现有 `express.static` 提供；业务文件不放静态目录 |
| 会话 | 复用 `express-session` 与 `transweb-token`，扩展 `session.data` 字段 |
| 接口注册 | 在 `interface/index.js` 的 `apiFiles` 中增加 `oa: "oa.js"`，由 `RestFulConfig` 自动注册 |
| 限流与跨域 | 复用现有 `express-rate-limit`、`CrossOrigin` 与 CSRF 同源校验 |
| 部署与备份 | 复用 `transweb` CLI 的启停、配置与数据目录约定，新增 OA 备份任务 |
