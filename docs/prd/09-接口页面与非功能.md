# 9 接口设计

## 9.1 接口约定

### 9.1.1 基础约定

| 项目 | 约定 |
| --- | --- |
| 协议 | HTTPS（内网亦建议启用；HTTP 仅用于调试） |
| 前缀 | `/oa`，与平台既有 `/user`、`/gpt`、`/admin` 接口隔离 |
| 数据格式 | 请求与响应均为 JSON（上传为 multipart/form-data） |
| 字符集 | UTF-8 |
| 时间格式 | ISO 8601，带时区，如 `2026-11-04T18:30:00+08:00` |
| 分页 | `pageNo` 从 1 开始，`pageSize` 默认 20、最大 100 |
| 排序 | `sortBy` + `sortOrder`（asc、desc），默认按更新时间倒序 |
| 幂等 | 写操作支持 `requestId`，相同 requestId 在 10 分钟内返回首次结果 |
| 鉴权 | 浏览器使用 Cookie 会话；系统间调用使用 `Authorization: Bearer ak_live_...` + Scope |
| 权限 | 每个接口标注功能权限编码；接口内先鉴权后执行，拒绝时记审计 |

### 9.1.2 响应结构

```json
{
  "ret": 0,
  "message": "",
  "data": {},
  "requestId": "req_20261104_0001"
}
```

`ret` 取值沿用现有约定：0 成功，1 业务失败，3 无权限。HTTP 状态码：401 未登录、403 无权限、404 资源不存在、409 状态冲突、413 文件过大、429 请求过频、500 服务异常。

### 9.1.3 权限编码

| 编码 | 说明 |
| --- | --- |
| doc.read / doc.upload / doc.edit / doc.delete / doc.archive / doc.grant | 文档类权限 |
| approval.submit / approval.approve / approval.config | 审批类权限 |
| permission.request / permission.approve / permission.ledger | 权限类权限 |
| audit.read / audit.export | 审计类权限 |
| sys.user / sys.role / sys.dept / sys.config / sys.backup / sys.sync | 系统管理权限 |
| stats.read | 统计查看 |

### 9.3.5 统一认证回调

```http
GET /oa/auth/callback?ticket=ST-1234-abcdef
```

处理逻辑：校验票据 → 获取用户属性 → 映射或创建账号 → 写会话 → 302 跳转回 `redirect` 参数。失败跳转 `/oa/login.html?error=SSO_FAILED`，不建立会话。

## 9.4 与现有框架的集成

| 集成点 | 做法 | 影响范围 |
| --- | --- | --- |
| 接口注册 | `interface/index.js` 的 `apiFiles` 增加 `oa: "oa.js"`；`interface/oa.js` 用 `document/list`、`approval/todo` 等分组键导出任务，`RestFulConfig` 生成 `/oa/document/list` 这类路径；也可拆成 `oa.js`、`oaApproval.js` 多个 apiFile 分别注册 | 新增文件，不改动既有接口 |
| 鉴权 | 新增 `custom/OaAuth.js`：`require(permission, handler)` 统一校验会话、账号状态、功能权限、密级；API Key 通过 `requiredScope` 校验 | 仅 OA 接口使用 |
| 审计 | 新增 `custom/OaAudit.js`：提供 `write(event)` 与 `wrap(action)`，业务成功后同步写入 | 仅 OA 接口使用 |
| 文件 | 新增 `custom/OaStorage.js`：保存、读取、流式输出、哈希、水印、临时清理 | 独立目录，不影响 bucket |
| 认证 | 新增 `custom/OaSso.js`：CAS 与 OIDC 适配，参数来自 `common.js` 与 `.env` | 新增入口，保留本地应急登录 |
| 页面守卫 | `webServer.js` 在 `express.static` 之前增加 `/oa/` 守卫：未登录访问业务页 302 到 `/oa/login.html`，登录页与静态资源放行 | 新增中间件，顺序与现有 `/bucket/personal/` 守卫一致 |
| 索引初始化 | 新增 `custom/OaDb.js` 的 `ensureIndexes()`，服务启动时调用一次，失败降级为告警不阻塞启动 | 启动阶段 |
| 配置 | `interface/config/common.js` 增加 `oa` 段：`session`、`upload`、`watermark`、`sso`、`approval`、`storage` | 追加配置，既有配置不变 |
| 环境变量 | `.env` 增加 `OA_SSO_PROTOCOL`、`OA_SSO_LOGIN_URL`、`OA_SSO_VALIDATE_URL`、`OA_SSO_CLIENT_ID`、`OA_SSO_CLIENT_SECRET`、`OA_SSO_REDIRECT_URI`、`OA_STORAGE_ROOT` | 新增变量，示例写入 `.env.example` |

> 所有改动遵循"新增文件优先、既有逻辑最小改动"的原则；不修改既有 `/user`、`/gpt`、`/admin` 行为，确保平台原有功能与计费不受影响。

### 10.2.2 文档中心（P03）

- 左侧分类树固定宽度 240px，支持搜索分类；选中分类后列表刷新。
- 顶部检索框支持标题、编号、标签；高级筛选以抽屉形式展开，条件可保存。
- 列表列：标题（含密级标识）、编号、分类、归属部门、状态、版本、更新时间、操作。
- 操作列按权限与状态动态渲染：预览、下载、编辑、归档、授权、更多。
- 批量选择后出现批量工具条：批量归档、批量授权、批量删除，操作前显示影响条数。
- 空状态区分"无数据"与"无权限"两种文案，后者提供申请入口。

### 10.2.3 文档详情（P04）

- 顶部：标题、编号、状态标签、密级标签、操作按钮（预览、下载、编辑、归档、授权、更多）。
- 左侧主区：预览区（PDF/图片/Office 转换）、版本切换、页面缩放。
- 右侧信息区：属性、可见范围摘要、当前授权人数、关联审批、有效期。
- 底部 Tab：版本记录、授权记录、审批记录、操作时间线；时间线按时间倒序，支持按类型筛选。
- 敏感文档在预览区右上角显示"敏感"角标与"下载需审批"提示。

### 10.2.4 审批详情（P09）

- 顶部：实例编号、事项名称、状态、发起人、发起时间、当前环节、剩余时限。
- 主区：表单字段只读展示、附件列表（可预览）、历史意见（按轮次分组）。
- 右侧：流程进度条（节点、处理人、结果、耗时），当前节点高亮。
- 底部处理区（仅当前处理人可见）：意见输入框、附件上传、同意/退回/驳回按钮；退回需选择目标节点，驳回需填写理由。
- 已办结实例隐藏处理区，显示"办结信息"与"导出审批单"。

### 10.2.5 权限台账（P13）

- 顶部筛选：人员/部门、文档/分类、权限项、来源、状态、到期时间。
- 列表列：被授权人、对象、权限项、来源、生效时间、到期时间、状态、审批单号、操作。
- 到期预警区：7 天内到期、已过期未处理，支持批量续期（走审批）与批量收回。
- 导出：按当前筛选条件导出 Excel，导出行为记录审计。
- 复核模式：生成季度复核清单，逐项标记"保留/收回"，生成复核报告。

### 10.2.6 审批模板配置（P18）

- 左侧事项列表，右侧配置区，分为"基本信息 / 表单设计 / 流程设计 / 规则"四个 Tab。
- 表单设计：字段库拖入画布，右侧设置必填、默认值、校验；支持字段排序与删除。
- 流程设计：节点卡片纵向排列，选择节点类型与审批人来源；节点间连线表示串行；会签/或签在节点内配置。
- 保存前校验：至少一个节点、审批人可达、时限合法；校验失败定位到具体节点。
- 提供"预览"与"试运行"（不产生真实待办），降低配置错误风险。

## 10.3 前端实现约定

| 约定 | 说明 |

## 11.2 安全与合规

按网络安全等级保护二级要求落实，重点控制项如下：

| 控制点 | 措施 |
| --- | --- |
| 身份鉴别 | 统一身份认证；密码不出现在日志；连续失败锁定；会话超时与并发控制 |
| 访问控制 | RBAC + 数据范围 + 文档授权 + 密级；默认拒绝；接口逐项鉴权；越权尝试记日志 |
| 安全审计 | 登录、文档、授权、审批、配置全留痕；日志只追加；保留不少于 6 个月；支持完整性校验 |
| 数据完整性 | 文件 SHA-256 校验；审批与授权使用乐观锁；备份校验值 |
| 数据保密性 | 传输 TLS；敏感文档水印；备份加密；密钥放 `.env` 不入库不入代码 |
| 备份恢复 | 每日备份，保留 30 天；季度恢复演练；RPO ≤ 24 小时、RTO ≤ 4 小时 |
| 剩余信息保护 | 删除文件后清理存储；临时文件定时清理；会话登出即失效 |
| 个人信息保护 | 仅采集必要信息；手机号、邮箱脱敏展示；导出需授权并留痕 |
| 上传安全 | 类型白名单 + 黑名单双重校验；大小限制；文件名安全化；不在服务端执行上传内容 |
| Web 安全 | 沿用 CSRF 同源校验、CORS 白名单、限流、XSS 转义、点击劫持防护 |
| 权限最小化 | 内置角色最小权限；系统管理员不默认读正文；临时授权到期回收 |

## 11.5 可维护性与扩展性

1. **配置化**：审批模板、字典、参数均可在界面配置，减少改代码。
2. **接口分层**：页面只依赖 `/oa` 接口；后续替换数据库或接入学校其他系统时不影响前端。
3. **数据库可替换**：数据访问封装在 `custom/OaDb.js`，如需 MySQL，可按现有 `interface/xml` 方式新增查询配置并实现同一接口。
4. **预留扩展点**：电子签章、短信通知、企业微信/钉钉、全文检索引擎均以适配器方式预留，不侵入核心流程。
5. **日志规范**：统一 `requestId` 串联前后端日志，便于排障。
6. **文档与交接**：交付接口文档、数据字典、部署手册、运维手册与操作手册，确保院系可自行维护。
