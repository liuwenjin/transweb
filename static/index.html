为教师、研究者与一线团队而设计

一页看懂 TransWeb

  • TransWeb 数字劳动力是指运行在浏览器里的 AI 同事：不装客户端、不配服务器，打开网页即可创建。
  • 上岗通常约 3 分钟：上传资料或一句话生成技能，把技能拼成工作流，用链接或二维码一键交付。
  • 计费方式为按量计费：没有席位订阅，闲置时费用为 0。
  • 资料按账号隔离、不用于公共模型训练；私有化部署接入自有模型时，数据可全程留在内网。
  • 适合教师、HR、研究员、顾问等需要「把资料变成岗位能力」的个人与机构。
HOW IT WORKS

三步开一个工位，它就开始上班。

TransWeb 数字劳动力的上岗流程共 3 步：打开网页、喂进资料、交付出去——全程在浏览器里完成，不装客户端、不写部署脚本，通常约 3 分钟即可上岗。

01 / LAUNCH

打开 · 即用

TransWeb 的网址就是工作台：数字劳动力的创建、预览、发布都在同一个页面里完成，不用装客户端，也不用买服务器。

02 / LEARN

上手 · 会干活

上传 PDF、Word、Markdown，或一句话生成技能、把技能拼成工作流，数字劳动力会按业务需要长出岗位能力。

03 / WORK

上岗 · 出结果

数字劳动力负责查资料、跑流程、出结论；用链接或二维码交付后，接收方打开浏览器就能用，创建者不在场也不停工。

WHO USES IT

四类人，一支数字团队。

TransWeb 数字劳动力目前覆盖 4 类岗位场景：AI 助教（教师与教研组）、带教师傅（HR 与主管）、研究助理（研究员与分析师）、领域顾问（服务机构）。四类场景的做法相同：把每天要讲的资料交给数字劳动力，它优先依据资料原文回答，交付链接即可上岗。

谁在用中小学教师、教研组、培训讲师、学生

把教材、讲义、课件交给 AI 助教后：学生问「这道题怎么解」，AI 助教翻出原文一步步讲；老师要出卷，AI 助教照着知识点出题、批改。一位 AI 助教，全班随时能问。

TRANSPARENCY

不为席位付费，只为干活付费。

TransWeb 的计费方式是按量计费：只按模型实际用量与发布 / 导出操作结算，没有按人头订阅的套餐，闲置时费用为 0。

按量计费 = 模型调用积分 + 发布 / 导出服务费

注：「发布 / 导出服务费」不超过「模型调用积分」的 10%。

01 root 管理账号 最高优先级
配置概述

最高优先级：先取得管理端登录凭据，再配置算力、支付与登录验证码。

transweb root accessKey
transweb root accessKey --json

transweb root accessKey 输出 root 管理账号与万能验证。登录选「验证码登录」，验证码填万能验证；首次登录后请立即修改默认账号与密码，切勿将初始凭据暴露在公网环境。

02 算力供应方
配置概述

算力供应方是 TransWeb 接入大模型的通道：一个供应方对应一个 apiName，私有化部署至少配置 1 个。

transweb api add <apiName> \
  --url <url> \
  --key <apiKey>

算力供应方配置包含接入名与密钥：apiName 是自定义接入名（示例 dmxapi，也可以叫 深度求索），后续模型通过 --api-name 引用；--key 写入 .env 的 API_KEY_*，common.js 只保留引用。

03 model
配置概述

模型是数字劳动力实际调用的大模型：模型挂在算力供应方下，至少配置 1 个并设为默认。

transweb model add <model> \
  --api-name <apiName> \
  --input <rate> --output <rate> \
  --context <context> --from <国内|国外>

transweb default model --model <model>

模型配置定义调用与计费规则：至少 1 个，包含 apiName、费率与 from。费率 = 积分与 token 的比例：1 个 AI token 对应多少积分，输入 / 输出分别计费；from 填 国内 或 国外，context 为上下文 token 数。配置后执行 transweb default model 设为默认。

04 微信支付
配置概述

微信支付用于积分充值收款：正式收款前需配置 APIv2 参数，至少完成必填项。

transweb wxpay set <参数> <值>
transweb wxpay check

微信支付配置分为必填与按需两组参数：必填 WX_PAY_APP_ID、WX_PAY_MCH_ID、WX_PAY_APP_KEY（32 位 APIv2 密钥）、WX_PAY_ORDER_URL、WX_PAY_QUERY_URL；按需 WX_PAY_APP_SECRET、WX_PAY_NOTIFY、WX_PAY_APP_ID001 / SECRET001。用 transweb wxpay set 写入、wxpay check 校验；安装生成的 APP_KEY 是随机值，正式收款前替换为商户平台密钥。

05 登录验证码
配置概述

短信验证码服务用于手机登录与注册：未配置时手机验证码不可用。

transweb env set SEND_MESSAGE_API_KEY <key>

短信验证码配置只需 1 个 API Key：SEND_MESSAGE_API_KEY（螺丝帽短信），用 transweb env set SEND_MESSAGE_API_KEY 写入；未配置时手机验证码登录 / 注册不可用。

展开各配置项查看命令；完成后用 transweb api list、transweb model list、transweb default list 检查 AI 配置，微信支付用 transweb wxpay check，短信 Key 用 transweb env get SEND_MESSAGE_API_KEY 检查。API / model 同名配置已存在时加 --force。transweb root accessKey 与 transweb env get ADMIN_ACCOUNT / POWER_ADMIN 读取同一份 .env；修改后需 transweb restart 生效。

部署提示 6 条提示
  • 开源地址：github.com/liuwenjin/transweb
  • 上线前安全：务必执行 transweb admin hide ，避免后台入口（admin.html / initAdmin.html）暴露到公网；公网部署再设 TRANSWEB_DISABLE_ADMIN=1 兜底。
  • 初始化页面：初始化完成前 /initAdmin.html 自动可访问，初始化完成后自动返回 404；再次进入后台执行 transweb admin show。
  • 首次初始化：自动安装应用依赖（约 543 个包）并下载 MongoDB 6.0.x（约 58MB）。
  • 数据目录：服务目录默认 ~/.transweb-service，升级 npm 包不会丢失数据。
  • 局域网访问：其他设备可直接访问 transweb status里显示的地址。

QUESTIONS

常见疑问

关于它是什么、能不能真的干活、要不要装东西、数据与计费怎么算，这里回答最常被问到的几个问题。

AI 数字劳动力是指以浏览器为工作台、能按岗位完成多步任务的 AI 同事。它不要求安装客户端或准备服务器，打开网页即可创建、调试并交付。与只能对话的聊天机器人不同，数字劳动力可以读取你上传的资料、调用技能、按工作流跑完 3 类任务：查资料、跑流程、出结论。每个数字劳动力都绑定 1 份资料库与若干技能，优先依据资料原文作答，像人一样按岗位办事，而不是只回一句话。创建后通过链接或二维码交付，接收方打开浏览器就能使用，创建者无需在场。

三者的区别在于能力层级：聊天机器人只会对话，AI Agent 会调用工具，而数字劳动力更接近一个完整「岗位」。数字劳动力有 3 个组成部分：人设（岗位定位）、资料依据（专属知识库）与技能（可执行能力）。多个技能还能编成工作流，跑完多步骤流程，最后以链接、网页或二维码交付给具体的人使用。平台把三者统一为同一套积木：Agent 是执行者，技能是能力，工作流是工序。因此评估标准不是「能不能聊」，而是「能不能按岗位独立交付结果」。

在线使用不需要安装任何软件或准备服务器：浏览器就是工作台，数字劳动力的创建、预览、发布 3 个动作都在网页里完成。只有一种情况需要服务器——企业选择私有化部署时，才需要一台自有服务器，用一个安装包（transweb-service）把整套服务装进去；成员依然用浏览器访问，无需安装客户端。也就是说，个人和小团队可以零部署开始，院校和企业可以在数据不出内网的前提下使用同一套能力。
